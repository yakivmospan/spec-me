# Mid-work corrections

Always-on. When the user corrects something while work is under way — a quoted line, "bad example",
"what?", "I don't like this" — the work changes gear.

- **One correction, one edit.** Fix the thing pointed at with a single edit through the editing tool,
  read the file back around it, and only then take the next message. Nothing else rides along in that
  edit.
- **Say what was wrong before fixing it,** in one line, so a wrong reading is caught before the edit.
- **Then the kind, not the line:** the `remember-mistake` skill sweeps the whole current change for
  the same mistake and records it where that work is governed.
- **No claim without a read-back.** "Fixed", "mirrored", "already there", "no copy exists" are said
  only after the file was opened and seen; a tool result that could mean two things is checked a
  second way before it is reported.
